## 1. 프로젝트 소개

프로젝트 목표는 제목에서 알 수 있듯이 **LLM과 RAG를 이용한 교칙 기반 챗봇 제작**이다.  
실제로 대학 커뮤니티 앱 '에브리타임'에는 수많은 학칙 관련 질문이 매일 올라온다.  
신입생이든 재학생이든, 학칙을 잘 몰라서 혹은 찾기 귀찮아서 계속 질문을 올리는 경우가 많다.  
이런 문제를 해결하기 위해, 학칙에 기반한 정확한 답변을 제공하는 챗봇을 만드는 것이 본 프로젝트의 핵심이다.

## 2. 왜 RAG인가?

RAG(Retrieval-Augmented Generation)를 사용하는 이유는 두 가지다.

### 1. 데이터 최신성 보장

LLM은 학습 시 고정된 데이터를 기반으로 하기 때문에 최신 데이터를 반영하지 못한다.  
예를 들어 GPT는 2021년 이전 데이터까지만 알고 있다.  
따라서 특정 학교의 학칙 같은 정보는 아예 학습되어 있지 않을 가능성이 높다.

### 2. 프롬프트 길이 제한 문제 해결

모든 학칙을 프롬프트에 포함시키면 길이 제한에 걸릴 수 있다.  
또한 불필요한 정보를 포함하면 오히려 모델의 추론 정확도가 떨어진다.  
필요한 정보만 추출해서 LLM에 전달하는 방식이 더 효율적이다.

![[33-d9168425b4.png]]

RAG를 사용한 프로젝트의 아키텍쳐

예를 들어, 사용자가 “결석을 4번 하면 F인가요?”라는 질문을 하면,

1. GPT를 이용해 검색 쿼리를 생성하고,
2. 쿼리를 벡터화된 학칙 DB에 전달해 관련 정보 검색
3. 검색된 데이터 + 원래 질문을 LLM에 입력
4. 최종 응답 생성

## 4. 구현 과정

![[33-9c590ceab8.png]]

동국대 규정관리 시스템 홈페이지 -> Pinecone에 벡터화 해서 저장

### 📌 데이터 수집 및 전처리

- 동국대학교 규정관리시스템에서 학칙 데이터를 수집
- 단순 텍스트 저장은 유사한 문서 검색이 어려움 → **임베딩**
- 벡터 간 유사도 계산은 **코사인 유사도** 사용

### 📌 임베딩 및 검색 시스템

- **임베딩 모델**로 텍스트를 벡터화
- **Pinecone**을 이용해 벡터 검색 환경 구성

## 5. 응답 예시

![[33-2b653d832f.png]]

프롬프트: “결석을 얼마나 해야 F인가요?”  
→ 유사도 상위 3개 학칙 조항을 검색해 LLM에 전달  
→ 예: “학사과정 학칙 시행세칙 제46조 지각 및 결석” 조항 인용

프롬프트와 관련 없는 질문에는 **답변하지 않도록 설정**,  
할루시네이션을 억제할 수 있도록 구성함.

## 6. 복합 질의 처리

![[33-5eff3a5e79.png]]

두가지 이상의 검색 데이터로 답변을 한 결과

예: “군 휴학 신청은 어떻게 하고, 군 복무가 최대휴학연한에 포함되나요?”

- 학칙 제9장: 최대휴학연한 포함 여부
- 시행세칙 제16장: 군 휴학 신청 방법

→ 두 조항을 함께 사용해 정확한 응답 생성

## 7. 평가 방식

![[33-ba3ec50fc0.png]]

정확한 평가 방법은 아니다. 참고정도만 가능한 방법

- 정성적 평가 외에도 **GPT-4 자동 스코어링**을 통한 정량적 평가 진행
- 완전한 수치화는 어렵지만 응답 품질 확인용으로 활용

---

## 8. 추가 계획

- **오픈소스 LLM** (예: LLaMA2) 기반 전환 → 서버비 절감
- **파인튜닝**을 통한 응답 최적화
- **학교 공지사항** 크롤링 → 데이터베이스 확장 및 응답 범위 확대

---

이렇게 해서 검색과 답변이 가능한 챗봇 환경을 구현 완료했다.  
단순한 LLM 사용에서 벗어나 **RAG 기반 정보 검색**을 결합함으로써,  
정확도와 최신성을 모두 갖춘 챗봇을 완성할 수 있었다.
